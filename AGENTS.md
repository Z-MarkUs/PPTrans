# PPTrans repository guidance

## Scope

PPTrans v2 is a `src`-layout Python application for translating editable PowerPoint presentations. Its formatting-safe core inspects a `.pptx` package, creates an immutable translation plan, patches only addressed DrawingML text nodes in a staged copy, verifies the result, and atomically publishes a distinct output. Treat `.pptx` as the only supported deck format unless another format gains an explicit conversion path and integration coverage.

## Setup and commands

- Use a supported CPython release from 3.10 through 3.13.
- Install development dependencies with `python -m pip install -e ".[dev]"`.
- Run focused tests while iterating, then run the applicable gates in `docs/QUALITY_GATES.md`.
- Default tests must be offline and deterministic; pytest blocks in-process Python socket creation by default. That is not OS-level egress control and is not inherited by subprocesses. Never spend provider credits unless the user explicitly requests a separately invoked external-provider test and the required key is already available.

## Architecture

- `src/pptrans/domain/` owns immutable plans, patches, results, limits, and domain errors.
- `src/pptrans/ooxml/package.py` and `xml.py` own defensive ZIP/XML access and copy-on-write package serialization.
- `src/pptrans/ooxml/inspect.py` and `locate.py` own recursive shape/table discovery, stable paragraph locators, and source-guarded translation units.
- `src/pptrans/ooxml/patch.py` owns translation-shape validation and text-node-only patching.
- `src/pptrans/ooxml/verify.py` proves that package membership, unrelated parts, XML structure, and patched values meet the preservation contract.
- `src/pptrans/application/deck.py` stages, verifies, fsyncs, and atomically publishes translated output without overwriting the source.
- `src/pptrans/review/`, `src/pptrans/schemas/`, and `src/pptrans/adapters/renderers/` own bounded review policy, strict provider-neutral schemas, safe repair plans, and rendering adapters.

## Engineering invariants

- Never overwrite the input presentation. Write to a distinct output and use temporary paths for intermediate files.
- Preserve package member names and ordering. Unrelated members must remain byte-identical; targeted slide XML may differ only in validated text-node values while retaining its structural fingerprint.
- Preserve slide order, stable shape paths, geometry, relationships, media, and paragraph/run structure unless a separate documented repair operation is explicitly authorized and verified.
- Guard plans and patches with the source file hash and source-span digests so stale translations cannot be applied to a changed deck.
- Treat every model response as untrusted data. Never execute model-generated Python or shell code.
- Keep provider failures explicit and actionable; do not silently report a successful translation after a partial failure.
- Do not commit API keys, private decks, generated customer content, translation memories, or provider responses containing user data.
- Use self-authored synthetic decks for tests and demos.
- Back every performance, quality, compatibility, or formatting claim with a current test or benchmark. Otherwise label it as experimental or a limitation.

## Agent Skill maintenance

- `.agents/skills/pptrans-engineering/` is the canonical Agent Skill.
- `.claude/skills/pptrans-engineering/` is a generated byte-identical mirror for Claude Code. Do not edit it independently.
- After editing the canonical skill, run `python scripts/sync_agent_skills.py`, then `python scripts/validate_agent_skills.py`.

## Git hygiene

Preserve unrelated worktree changes. Do not publish packages, create releases, push branches, or change live repository settings unless the user explicitly authorizes that external action.
